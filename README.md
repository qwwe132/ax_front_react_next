# 회원별 할 일 목록

기존 JavaScript Todo 리스트를 Next.js로 옮기고, Supabase Auth와 PostgreSQL을 연동한 프론트엔드 응용 과제입니다.

## 기능

- 이메일 회원가입, 로그인, 로그아웃
- 날짜·제목·내용 등록 및 수정
- 등록순·날짜순 정렬
- 휴지통 이동, 복구, 영구 삭제
- 로그인한 회원의 할 일만 조회 및 변경

Next.js App Router와 React로 화면을 구성하고, Server Actions에서 Supabase를 호출합니다. 각 행의 `user_id`와 Supabase RLS 정책으로 소유권을 확인합니다.

## 로컬 실행

1. Supabase 프로젝트를 준비하고 아래의 데이터베이스와 이메일 인증 설정을 적용합니다.
2. 프로젝트 루트에 `.env.local`을 만들고 프로젝트 URL과 publishable key를 입력합니다.

   ```dotenv
   NEXT_PUBLIC_SUPABASE_URL=https://your-project.supabase.co
   NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY=your-publishable-key
   ```

3. 의존성을 설치하고 개발 서버를 실행합니다.

   ```bash
   npm ci
   npm run dev
   ```

4. 브라우저에서 `http://localhost:3000`을 엽니다.

## Supabase 데이터베이스

새 프로젝트에서는 SQL Editor에서 아래 SQL을 실행합니다. 기존 `todos` 테이블을 사용하는 경우에도 `user_id`와 소유권 정책을 추가할 수 있습니다.

```sql
begin;

create table if not exists public.todos (
  id bigint generated by default as identity primary key,
  date date not null,
  title text not null,
  content text not null,
  is_delete boolean not null default false,
  created_at timestamptz not null default now()
);

alter table public.todos
  add column if not exists user_id uuid references auth.users(id);

alter table public.todos alter column user_id set default auth.uid();
create index if not exists todos_user_id_idx on public.todos (user_id);
alter table public.todos enable row level security;

revoke select, insert, update, delete, truncate on public.todos from public, anon;
revoke truncate on public.todos from authenticated;
grant select, insert, update, delete on public.todos to authenticated;

drop policy if exists "Todo owners have access" on public.todos;
create policy "Todo owners have access"
  on public.todos for all to authenticated
  using (user_id = (select auth.uid()))
  with check (user_id = (select auth.uid()));

drop policy if exists "Todos require a signed-in owner" on public.todos;
create policy "Todos require a signed-in owner"
  on public.todos as restrictive for all to public
  using (
    user_id = (select auth.uid())
    and (select auth.jwt() ->> 'is_anonymous') is distinct from 'true'
  )
  with check (
    user_id = (select auth.uid())
    and (select auth.jwt() ->> 'is_anonymous') is distinct from 'true'
  );

commit;
```

기존 항목 중 `user_id`가 비어 있는 행은 DB에 남습니다. 해당 회원의 화면에 표시하려면 행의 소유자를 확인한 뒤 Supabase Authentication의 사용자 UUID를 지정합니다.

## 이메일 인증과 Vercel 배포

- Supabase Authentication에서 이메일 가입을 허용하고 Site URL을 앱 주소로 설정합니다.
- 이메일 확인을 사용하는 경우 **Confirm signup** 템플릿의 확인 링크를 아래 주소로 교체합니다.

  ```text
  {{ .SiteURL }}/auth/confirm?token_hash={{ .TokenHash }}&type=email
  ```

- Vercel에 이 GitHub 저장소를 연결하고 위의 환경 변수 두 개를 등록합니다. 배포 후에는 Supabase의 Site URL을 실제 배포 주소로 설정합니다.
